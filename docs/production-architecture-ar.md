# بنية الإنتاج المقترحة — المتجر العالمي سوريا

## المبدأ

تظل الحزمة الحالية نموذج واجهة ثابتًا قابلًا للمعاينة. لا تُعد حسابات المستخدمين أو الطلبات أو المخزون أو الدفع جاهزة للإنتاج قبل إضافة خادم وقاعدة بيانات ومصادقة واختبارات أمنية. يحافظ هذا الفصل على التزام المشروع بعدم إنشاء بيانات وهمية.

| الطبقة | التقنية الواردة في الملف | المسؤولية | الحالة الحالية |
|---|---|---|---|
| تطبيق الموبايل | Flutter / Dart | تسجيل الدخول، الأقسام، السلة، الدردشة، الطلبات والتتبع | مخطط فقط؛ النموذج الحالي HTML متجاوب |
| لوحة المتجر والإدارة | React.js / Next.js + TailwindCSS | إدارة المنتجات والكود والكمية والوصف والاشتراك والبلاغات | واجهات HTML أولية؛ تحتاج تحويلًا إلى تطبيق |
| الخلفية | Node.js / NestJS + TypeScript | المصادقة، الصلاحيات، الطلبات، الفواتير، WebSocket وAPI | غير مربوطة في الحزمة الحالية |
| قاعدة البيانات | PostgreSQL | المستخدمون والمتاجر والفئات والمنتجات والطلبات والرسائل | مخطط مطلوب؛ لا تحفظ النسخة الحالية بيانات خادمية |
| التخزين المؤقت | Redis | الجلسات المحدودة، التحديد المعدل، حالات التتبع المؤقتة | غير مفعّل |
| الوسائط | S3 أو Cloudinary | صور المنتجات ونسخ WebP والمعالجة | الحفظ المحلي للمسودة فقط في النموذج |
| الذكاء الاصطناعي | خدمة معتمدة بعد مراجعة الخصوصية | الوصف، الكلمات المفتاحية، الخلفيات، الضغط، المساعد | موثق فقط وغير مفعّل |

## عقود API الأولية

| المسار | الغرض | الصلاحية المطلوبة |
|---|---|---|
| `POST /auth/request-otp` | طلب رمز دخول | معدل طلب لكل هاتف أو بريد |
| `POST /auth/verify-otp` | إنشاء جلسة | موافقة الشروط مطلوبة |
| `GET /catalog` | البحث بالقسم والمحافظة والشحن | مستخدم مسجل |
| `POST /cart/items` | إضافة عنصر للسلة | المشتري صاحب الجلسة |
| `POST /orders` | إنشاء طلب وفاتورة مفصلة | المشتري؛ يتحقق من المخزون |
| `POST /rfq` | طلب عرض سعر للمتجر الكبير | مشتري مسجل |
| `POST /vendors/products` | حفظ منتج وكوده وكمية | تاجر موثق |
| `GET /vendors/subscription` | قراءة حالة التجربة والاشتراك | صاحب المتجر |
| `POST /reports` | بلاغ عن منتج أو رسالة | مستخدم مسجل |
| `DELETE /account` | طلب حذف الحساب | صاحب الحساب مع تأكيد إضافي |
| `WS /chat` | دردشة المنتج والطلب | مستخدمان مخولان فقط |

## قواعد أمنية قبل الربط

تُخزّن كلمات المرور باستخدام تجزئة قوية أو يُستخدم OTP موثوق دون حفظ الرمز بصيغته المكشوفة. تُفصل أدوار `CUSTOMER` و`VENDOR` و`ADMIN`، وتُفرض الصلاحية على الخادم لا على الواجهة فقط. تُحدد معدلات الدخول والبلاغات والرسائل، ويُمنع إدخال HTML أو SQL غير موثوق. تُحفظ أقل كمية لازمة من بيانات الدردشة، ويُسجل التدقيق الإداري دون كشف بيانات شخصية غير ضرورية.

لا تُفعّل رسوم الاشتراك الشهرية أو دفع المنتجات قبل تحديد نوع المعاملة ومراجعة سياسة Google Play والوسيلة القانونية والمحاسبية المتاحة. ولا يُفتح التاجر الخارجي قبل اتفاق مستقل وصلاحيات API محدودة وتقييم أمني وإفصاح خصوصية.
