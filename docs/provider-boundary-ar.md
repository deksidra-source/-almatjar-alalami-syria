# خطة الموردين وحدود التنفيذ — المتجر العالمي سوريا

## القرار التشغيلي الحالي

يعتمد المتجر في الإصدار الأول على **الدفع عند الباب** و**الدفع اليدوي** فقط. الدفع عند الباب يثبت كطريقة طلب داخل التطبيق، أما الدفع اليدوي فيسجل العلاقة بين المشتري والبائع، ثم يسجل المدير عملية التسوية اليدية مع التاجر. لا يُعرض أي دفع إلكتروني كأنه فعّال قبل توقيع اتفاق واستلام API رسمية وبيئة اختبار من مزود مرخص.

## ما ينفذ داخل المشروع

| الميزة | التنفيذ الداخلي | حالة العرض الحالية |
|---|---|---|
| التنقل والشريط السفلي | Expo/React Native | السلة في الوسط، والدعم تبويب مستقل |
| الهوية واللغات | قاموس ترجمة واتجاه ديناميكي | العربية RTL، والتركية والإنجليزية والصينية واليابانية LTR |
| السلة | حالة محلية + AsyncStorage | حفظ السلة عند انقطاع الشبكة |
| توفير البيانات | إعداد محلي وصور مصغرة لاحقًا | مفتاح Data Saver ظاهر في الحساب |
| الدفع عند الباب | نموذج طلب وحالة تأكيد | مفعّل تجريبيًا |
| الدفع اليدوي | سجل طريقة الدفع وحالة التسوية | مفعّل تجريبيًا بين الأطراف |
| الترويج | قواعد 7 أيام وأسعار المتجرين | مفعّل في غرف التاجر والإدارة |
| الدعم | شاشة محادثة أولية | جاهزة للربط بخادم الرسائل |
| مساعد القط | واجهة محلية ومسارات توصية | واجهة تجريبية، دون ادعاء ذكاء فعلي |
| تجربة الألوان | عينات ألوان وواجهة اختيار | واجهة تجريبية؛ الكاميرا تحتاج صلاحية ومكتبة أصلية |
| الشراء الجماعي والولاء | نماذج وقواعد داخلية | تحتاج ربطًا بقاعدة البيانات قبل الإنتاج |

## ما يحتاج موردًا أو موافقة خارجية

| المورد/المجال | المطلوب | لا يبدأ الإنتاج قبل |
|---|---|---|
| WhatsApp Business Platform | قالب Utility، Webhook، رقم أعمال، صلاحيات Meta | تسجيل opt-in واضح، HTTPS، وموافقة الحساب |
| SMS محلي | بوابة رسائل ورقم مرسل وقوالب | عقد مزود محلي، حدود أسعار، وسجل موافقات |
| شركة شحن | إنشاء بوليصة، Barcode، Tracking API، تحديث حالات | وثائق API وSandbox واتفاق مسؤوليات |
| نقاط PUDO | شبكة نقاط وعناوين وساعات عمل | قائمة شركاء حقيقية وسياسة OTP والاستلام |
| خرائط | Google Maps أو مزود بديل | مفتاح API وسياسة تكلفة وتغطية مناسبة |
| المحافظ الإلكترونية | Syriatel Cash أو Bemo أو مزود آخر | API رسمية، Webhook، تسوية، استرداد، ومراجعة قانونية |
| الفيديو | CDN/Video service أو عامل معالجة مستقل | سياسة تخزين واعتدال وحذف ومراقبة التكلفة |
| البحث المرئي | نموذج متعدد الوسائط أو فهرس embeddings | سياسة الاحتفاظ بالصور واختبار دقة على كتالوج حقيقي |

## تدفق الدفع اليدوي

ينشئ المشتري طلبًا باختيار الدفع عند الباب أو الدفع اليدوي. يحفظ النظام الطريقة المختارة وحالة الطلب `PENDING_CONFIRMATION`. عند قبول البائع يصبح الطلب `CONFIRMED`، وعند تسليم الطلب يسجل الموظف أو البائع `COLLECTED`. بعد ذلك ينشئ المدير قيد تسوية للتاجر يتضمن رقم الطلب، المبلغ، العمولة، المبلغ المستحق، طريقة التسوية، والمرفق الاختياري، ثم يوافق عليه أو يرفضه. كل تغيير يسجل في سجل تدقيق ولا يحذف من الواجهة.

## القاعدة الأمنية

لا تخزن المنصة أرقام بطاقات أو أسرار المحافظ داخل التطبيق. مفاتيح التكامل تحفظ في الخادم، والعميل يحصل على حالة فقط. كل Webhook يتحقق من التوقيع ويقبل التكرار الآمن، وكل OTP للاستلام أحادي الاستخدام ومنتهي الصلاحية. أي صور أو فيديوهات يرفعها المستخدم تمر بقيود الحجم والنوع والإبلاغ والحذف.

## ترتيب التنفيذ

يبدأ العمل بتثبيت السلة المحلية وData Saver وموقع التسليم والدفع عند الباب والدفع اليدوي. بعد اختبار ذلك على شبكة ضعيفة، يضاف البحث بالصور والشراء الجماعي والولاء. بعدها يربط المشروع شركة شحن واحدة، ثم WhatsApp/SMS بعد opt-in، ثم PUDO والتجميع، وأخيرًا كل محفظة بعد وثائقها الرسمية.
